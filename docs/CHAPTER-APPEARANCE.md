# Shared appearance and native notebook visual parity — work in progress

The original web application stores appearance **only in localStorage**. Chapter adds an optional `settings.chapterAppearance = {v:1,mode,palette,skin}` inside the **existing encrypted `aiSettings` record**. This is an application extension, not a cryptographic change: original keys, ciphers, AAD, record kind, wire clock and server endpoints are unchanged. The name of the carrier does not enable AI; theme-only bootstrap uses disabled defaults, empty credentials and makes no provider request. Existing settings, credentials and unknown fields are retained. Resetting AI configuration in the updated Chapter web client clears its credentials while retaining appearance.

- Explicit choices sync. Initial local defaults are never uploaded automatically.
- Six original skins and six original accents; light/dark/system. Choosing a skin adopts its original default accent; choosing an accent afterwards overrides it. System means follow **each device's** OS, not force a remotely observed light/dark state.
- The native color resource is generated from actual original `tokens.css` and `useTheme` catalogs. Browser regression checks reject resource drift. Run `pnpm --filter client exec tsx scripts/native-theme-vectors.ts --write` only deliberately when changing the original tokens; this also refreshes public interop fixtures.
- Unknown preference versions are retained and refuse edits. Unknown fields in supported v1 preferences/settings survive updates. Changes must reach encrypted local storage before the native model reports success.
- A new native device cannot create a theme-only settings record until its first full pull completes; downloaded existing settings remain editable offline. This avoids replacing previously unseen AI configuration with disabled defaults during offline onboarding.
- Native notebook thumbnails translate the original **mobile** `Cover` in `src/ui/primitives.tsx`: tinted translucent background, colored spine, five patterns, border and original dimensions/radius. `photo` is a diagonal pattern, not a fetched photo. No external content request is added. RTL moves the spine. This is not yet a declaration of whole-app visual parity: native fonts, surfaces, spacing, structural content and screenshots require review.

## Actual verification gates

Local browser checks include all 108 mode/accent/skin combinations, original CSS colors, preservation of API/opaque/future fields, disabled bootstrap and unknown-version rejection. The actual Swift Foundation mutation/catalog source is also exercised on Linux without making any cryptographic/runtime claim.

Required macOS tests exercise original web ciphertext → native read/edit → encrypted snapshot restart → native ciphertext → actual web decoder, unknown versions, overflowing clocks, equal-clock recovery and backup metadata preparation failure without replacing existing ciphertext. The real TLS/Go/Postgres workflow additionally seeds settings with the actual web client, pulls with native URLSession over normally validated TLS, persists offline changes and reloads, pushes native preferences, rejects an older web write, and verifies the actual web pull/decoder. These are **pending until the feature commit's CI actually passes**. Native screenshot test captures original notebook covers and Forest skin; do not describe screenshots as reviewed until downloaded and inspected.

## Conflicts / older-client limits

Existing original settings LWW semantics still apply; no replacement protocol is introduced. Native equal-clock divergent values are both retained. The explicit “Apply recovered appearance” action re-patches only appearance over current settings, preserves current credentials and advances the checked clock; it does not delete recovered versions. This is not automatic semantic merging of simultaneous AI-key edits. The original browser settings provider still has broader asynchronous persistence/conflict limitations; strict equal-clock browser conflict convergence and fault-injected UI/provider race tests are outstanding release acceptance items, not proven by codec tests.

Old upstream web clients cannot synchronize their local theme UI. Their codecs preserve this unknown optional field during ordinary settings edits, but an old client's explicit settings clear/reset may remove the extension. Use updated Chapter web and native clients for shared appearance. Server changes are unnecessary. No snapshot format/key change, account migration or deployment is performed.

## Atomic local save correction

Backup-exclusion metadata now applies to the dedicated, app-owned vault directory **before** atomic ciphertext replacement. There is no throwing backup metadata operation after content commit. This closes the identified memory-versus-disk divergence if the old post-write metadata call failed. File protection and AES-GCM format remain unchanged. Fault injection tests must prove old encrypted bytes survive preparation failure, can reopen with the same key and subsequently save successfully. This is a scoped correction, not proof against every filesystem/device failure. The public storage initializer expects a dedicated owned directory; do not pass a shared unrelated-data directory.
